# Humanizer-cn：一个专门去除中文"AI 味"的开源 Skill，支持 DeepSeek Harness 一键安装

## 缘起

用 AI 辅助写作的人越来越多，但 AI 生成的中文有一种一眼就能认出来的"腔调"：

- 开口就是"这不仅是一个……更是……"
- 段落结尾总要来一句"总而言之，让我们拭目以待"
- 任何小事都能"标志着一个新时代的到来"
- 三句话不离"赋能""闭环""至关重要"

这些表达不是语法错误，而是模型的默认选择：它总挑那种对最多读者、最多场景都成立的写法，结果就是正确的废话。GitHub 上的 [Humanizer](https://github.com/blader/humanizer) 项目把 Wikipedia 编辑们总结的 [Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing) 做成了一个 Agent Skill，专门改写这类文字。但它只针对英文。

所以我做了 **Humanizer-cn**：把这套思路完整搬到中文，并补上了 DeepSeek Harness（DSH）插件支持。项目地址：

```text
https://github.com/xxjwxc/humanizer_cn
```

## 它是什么

Humanizer-cn 不是一个检测程序，也不是一个独立软件。它是一份由 AI Agent 读取并执行的编辑指导（Agent Skill），核心是一个 `SKILL.md` 文件。Agent 读到它之后，就按里面的 31 条编辑规则改写你给的文本。

两个设计原则值得单独说：

**第一，保真优先于去痕迹。** 很多"降 AI 味"的做法会把文章改得面目全非。Humanizer-cn 的约束有明确的优先级：保留信息和确定程度 > 用户的编辑范围与文体 > 作者声音 > 具体表达问题。换句话说，"可能"不会被改成"确定"，"计划推出"不会被改成"已经推出"，数据来源、否定、条件、归因一律不动。模式命中不能成为删改事实的理由。

**第二，规则是检查线索，不是词语黑名单。** 排比、破折号、被动句、四字格本身都不是错误。每条规则都带"保留边界"：作者有意的强调、真实的不确定性、邮件里的礼貌用语，都原样保留。没有问题的段落，一个字都不改。

## 31 条模式，6 条专为中文定制

规则按 A–F 分组，前 25 条覆盖通用写作问题，F 组 6 条专门处理中文特有的 AI 腔：

| 组 | 内容 |
|---|---|
| A. 铺垫代替陈述 | 假对比、单句收尾、格言与伪深度、起跑式铺垫、与假想敌辩论 |
| B. 公式化节奏 | 强凑三段式、句式开头复读、破折号滥用、限定词堆叠、生造复合词、被动与缺主语 |
| C. 拔高与借权威 | AI 高频词、意义拔高、模糊关联、句尾拔高、宣传语、借权威、回避"是／有" |
| D. 公式化排版 | 粗体当装饰、装饰性标题、引号与标点不统一 |
| E. 聊天与草稿残留 | 客服腔、知识边界免责、首句复读标题、谈论上一稿 |
| F. 中文补充检查 | 层叠的"的"、"进行＋动词"、被字句堆叠、四字词排比、"随着……的发展"式开头、套话收尾 |

看两个例子。

假对比（A 组）：

> 改写前：这不仅是一个导出按钮，更是通往高效工作的全新入口。它可以导出 CSV。
>
> 改写后：这个按钮可以导出 CSV。

"进行＋动词"（F 组）：

> 改写前：我们正在对系统进行全面测试，并计划在周五进行配置调整。
>
> 改写后：我们正在全面测试系统，并计划在周五调整配置。

注意第二个例子里，"正在"和"计划"都保留了——去的是冗长句式，不是时态信息。

## 安装

### DeepSeek Harness（DSH）

仓库根已经声明了 `dsh.bundle` 组合包，可以直接在 DSH 的插件安装页填仓库地址：

```text
https://github.com/xxjwxc/humanizer_cn
```

装完重启 `dsh web` 生效，激活时插件会自动把技能文件装入 `~/.dsh/skills/`。

也可以手动装：把仓库里的 `.dsh/skills/humanizer-cn.md` 复制到 `~/.dsh/skills/`（用户级）或项目下的 `./.dsh/skills/`（项目级），重启会话即可。

### Claude Code

```text
/plugin marketplace add xxjwxc/humanizer_cn
/plugin install humanizer-cn@humanizer-cn
```

### Codex 及其他 Agent

```bash
npx skills add xxjwxc/humanizer_cn --global --agent '*'
```

Skills CLI 不认识的 Agent，直接把 `SKILL.md` 复制到它的技能目录就行。

## 使用

装好后输入 `/humanizer-cn`，或者用自然语言：

```text
请用 humanizer-cn 润色下面的文章，保留技术评论的语气：
[原文]
```

也可以直接指向文件：`请用 humanizer-cn 润色 article.md 中的正文。`文件模式下只改正文，代码块、命令、路径、链接、YAML 元数据都原样保留。只想听意见就说"给出建议，不修改文件"。

如果你有自己写的文章，可以贴两三段作为样本，改写会模仿你的句长、用词和叙述习惯，而不是套一个统一的"人味"模板。

>
> 改写后：这次更新新增 CSV 导出、全文搜索和批量重命名。离线编辑计划在下一版推出，目前尚未完成测试。

宣传句删了，三个功能一个没少，"计划推出、尚未完成测试"的状态原封不动。这是它和"洗稿"式工具最大的区别：**它只做编辑，不做编造**。

## 写在最后

项目基于 blader/humanizer v3.1.0 修订而来，MIT 协议开源，规则清单、示例和边界条件全部公开在仓库里，改哪条、怎么改，你都可以自己定。

需要说明：它编辑的对象是"给读者看的文字"，目标不是骗过 AI 检测器，检测器大概率仍然会标它的输出。但读文章的是人，让人读起来舒服，才是正经事。
